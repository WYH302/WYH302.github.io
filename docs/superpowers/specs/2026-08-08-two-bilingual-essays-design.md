# 两篇双语博客发布设计

日期：2026-08-08

## 目标与范围

在现有静态个人网站中新增两篇独立博客，每篇同时提供英文和简体中文版本。文章保持鲜明立场，但把事实、推断和规范性主张分开；所有可核查的新闻、论文与历史事实使用可访问来源支持。此次工作不修改或提交工作区中已有的 CV、简历、安全检查等无关改动。

两篇文章都要进入双语博客目录、集中路由表、发布清单、发布时间映射和 sitemap，并通过现有的语言配对、发布时间、隐私、链接与发布安全测试。

## 文章一：AI 审权与算法治理

- 中文标题：**把权力交给 AI，还是让 AI 盯住权力？**
- 英文标题：**Should AI Rule, or Should It Audit Power?**
- 路径：`posts/ai-audits-power-algorithmic-governance/` 与 `zh/posts/ai-audits-power-algorithmic-governance/`
- 核心主张：AI 无法提供绝对公平，但可以降低审计成本，使公共权力和组织决策更容易被检查、解释和申诉。制度目标是让不公平更容易暴露、更难掩盖，而不是把最终统治权交给模型。

### 论证结构

1. 解释“AI 当领导”为何具有吸引力：它承诺削弱裙带、人情和私人偏好。
2. 说明算法中立的边界：训练数据、目标函数和公平定义都包含价值选择，不同统计公平标准无法在一般条件下同时满足。
3. 分析权力转移：模型没有消灭权力，指标制定者、数据管理者和系统运营者获得了新的裁量权。
4. 提出“AI 审权”制度：决策留痕、公开指标、独立审计、利益冲突披露、解释权、申诉权以及人类责任签署人。
5. 讨论技术改革被收编的风险：数据涉密范围扩张、表演式透明、选择性审计和“AI 治民”。
6. 校准历史类比：印刷术和工业化降低组织与传播成本，但政治联盟、社会动员和制度谈判才把技术能力转化为权力变化。
7. 结论：技术可以压缩暗箱空间，无法替社会决定何为公平。

### 证据边界

- 核验算法公平不可能性、社会技术系统中的公平抽象、公共部门算法问责与风险管理资料。
- 1832 年英国议会改革只作为有限选举权扩张案例，不描述为土地贵族彻底交权或普遍民主化。
- 印刷术与宗教改革只主张关联机制，不写成单一技术决定论。
- 不使用未经验证的“技术合法性挤压”作为既定学术术语。

## 文章二：长聘考核与高校代际更替

- 中文标题：**“铁饭碗”碎了，青年教师就能上桌吗？**
- 英文标题：**If the Academic Iron Rice Bowl Breaks, Do Young Scholars Get a Seat?**
- 路径：`posts/tenure-review-youth-and-university-renewal/` 与 `zh/posts/tenure-review-youth-and-university-renewal/`
- 核心主张：长聘教师应承担持续的岗位责任，但考核改革不会自动把岗位和资源交给青年。改革是否进步，取决于分类评价、正当程序以及腾出资源的明确转移规则。

### 事实基线

- 同济大学自 2019 年起推进长聘教职体系，专业技术岗位考核续聘并非 2026 年突然出现的新制度。
- 公开的 2025 年年度考核通知覆盖全体教职工；2025 年专业技术职务通知继续开展考核续聘；2026 年院系活动提到新版续聘考核标准。
- 现有公开材料不能证明同济计划清退一半资深教授，也不能支持全国高校将迅速按固定比例裁撤长聘教师。

### 论证结构

1. 解释改革的正当诉求：职称和长聘不应免除教学、科研、育人与服务责任。
2. 区分年度考核、岗位聘期考核、预聘晋升和长聘保障，避免把不同制度统称为“取消终身教职”。
3. 检验“顶层与青年联手挤压中层”假说：管理层、头部团队和青年学者可能共享部分目标，但资源网络与师承关系使三者并非稳定联盟。
4. 分析资源流向：人员降岗不等于新增青年岗位，学校可能核减编制或把资源再次集中到头部团队。
5. 说明单一论文指标的代价：基础教学、工程经验、团队服务和高风险长期研究可能遭到挤压，资深人员也可能通过挂名和任务转包满足指标。
6. 提出改革条件：分类评价、较长考核周期、同行实质审查、署名规范、公开标准、申诉程序、青年独立 PI 权利，以及编制、经费和研究生名额的可追踪转移。
7. 结论：考核应处理长期不履责的岗位占有，不能以年龄和代际标签代替证据。

### 表达边界

- 不沿用“混吃等死”“清算”“绞杀”等对群体进行人格化定罪的措辞；保留对制度性不公平和资源占有的批评。
- 不把不会写代码、短期没有论文或年龄较大直接等同于不合格。
- 明确区分新闻事实、制度推断和作者立场。

## 页面与发布设计

1. 以现有文章页面为模板创建四个 HTML 文件，设置正确的 `lang`、canonical、Open Graph、`article:published_time`、语义化 `<time>` 和双向语言链接。
2. 两篇文章使用同一精确发布时间，中文显示北京时间（UTC+8），英文显示 UTC+8；博客目录按时间倒序排列。
3. 更新 `scripts/bilingual-routes.mjs`、`scripts/publish-manifest.mjs`、`scripts/post-publication-times.mjs`、两套博客目录和 `sitemap.xml`。
4. 扩展现有测试，验证两个 slug 均已发布、资料链接存在、双语配对正确、时间只出现一次并保持倒序。
5. 不依赖 JavaScript 翻译器；中英文内容分别人工撰写并作为静态页面发布。

## 验收标准

- 四个新页面均能构建并通过本地链接检查。
- 两篇文章在英文和中文博客目录中各出现一次。
- 语言切换停留在同一篇文章，`hreflang`、canonical 和 sitemap 完整。
- 新闻和论文引用可访问，文章不把推断写成事实。
- `npm.cmd run test:coverage`、`npm.cmd run audit` 和依赖安全审计全部通过。
- 只提交本任务文件，保留用户已有未提交改动。
- 推送后核验 GitHub Actions/Pages，并在英文、中文页面上检查标题、发布时间和语言切换。
