Multimodal agents for computational imaging

I want to explore whether an agent can use measurement results to choose the next sensing and reconstruction step. This is still a research proposal; these are the questions I want to test and some possible approaches.

Motivation

Computational imaging turns physical measurements into images, then uses those images to answer questions. I am interested in the choices a person makes along the way: what remains unclear, what another measurement should resolve, and whether a different reconstruction method is worth trying. Having an agent help make those choices is closer to my research interest than asking it to describe a finished image.

Research questions

The representation question comes first: how can optical measurements, sparse observations, and reconstructed images enter one reasoning process without confusing the evidence each supplies? At the tool level, I would want simulators, reconstruction modules, segmentation models, and evaluation scripts to return inspectable results, including failures and uncertainty. That would give the next decision a basis: request more measurements, change the sensing strategy, or defer a prediction.

Possible direction

In the prototype I have in mind, the physical model and reconstruction tools remain in place. The agent chooses among them. Each choice keeps its inputs, call parameters, and outputs so I can inspect its basis. I would start with a small set of available actions and expand it only when there is a workable way to judge whether the preceding action helped.

Consider a hypothetical imaging task with a limited measurement budget. After an initial reconstruction, an edge remains unclear. The agent could request another measurement or compare a different reconstruction method. I would want it to identify the uncertainty and explain which competing account the proposed action could rule out, rather than say that image quality needs improvement. This is a workflow to test, not a report of an experiment already completed.

If two reconstruction methods disagree about an edge, their disagreement is not yet a reliable uncertainty estimate. The prototype should preserve it and check it using independent measurements or a predefined evaluation procedure. If the budget runs out, it should return the unresolved region and the reason for stopping. A convincing image must not stand in for missing measurements.

Test one small decision first

The first experiment need not give an agent control of an entire instrument. I would narrow the question to selecting the next measurement from a given set: does that choice help more than a fixed order? Candidate actions, costs, and available information would be specified in advance. Giving the agent just this decision makes it easier to distinguish an unhelpful choice from a failed tool call.

I would keep a simple selection rule in the comparison, such as a predefined measurement order, rather than test only against a deliberately weak pipeline. If the agent adds explanation and execution overhead without improving results under the same budget, that part of the workflow may not need it yet. Finding where more elaborate reasoning earns its cost would itself be useful.

Practical caution

I would give the fixed pipeline and the agent pipeline the same initial information and measurement budget, while recording extra computation, failed tool calls, and human intervention. Reconstruction quality matters, but so does usefulness for the downstream task. Obtaining a better image with twice the measurements differs from choosing better within the same budget.

I particularly want to keep attempts that do not help. Did an added measurement repeat information already available? Did another algorithm change the appearance without improving the answer? Did the agent overlook a sensor constraint? Those records would help me decide whether to change the selection strategy, the tool interface, or the question I started with.
